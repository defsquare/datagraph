# Journal d'exécution — passe UX globale

Compte rendu de l'exécution du plan
[`2026-09-08-ux-pass.md`](../plans/2026-09-08-ux-pass.md), qui met en œuvre la
spec [`2026-09-08-ux-pass-design.md`](../specs/2026-09-08-ux-pass-design.md).
Seize tâches, trente-et-un commits, `f7117a1..947f38d`.

Ce fichier était le journal de bord d'une exécution pilotée par sous-agents (une
tâche = un implémenteur + un relecteur, puis une revue finale de branche). Il est
conservé pour ce que l'historique git ne dit pas : **les décisions prises sans
demander à l'humain, et leur raison**. On y trouve, en clair :

- les lignes `Ruling:` — chaque arbitrage rendu en cours de route, avec ce qu'il
  coûte s'il est faux. Neuf d'entre eux corrigent des **défauts du plan
  lui-même** (un test visant une fonction inexistante, une règle CSS perdant la
  cascade, un `expand()` incapable de bouger le compteur qu'il prétendait
  vérifier, un correctif de recherche laissant un double pas sur Entrée) ;
- les lignes `minor (deferred)` — les remarques de revue volontairement non
  traitées, et pourquoi ;
- la ligne `parked` — la seule constatation réelle laissée en l'état, avec son
  raisonnement (la revue finale a confirmé l'arbitrage) ;
- la revue finale, qui a trouvé **deux régressions critiques** qu'aucune revue
  par tâche ne pouvait voir : le plancher de dézoom rendait le dézoom inopérant
  sur tout contenu cadré au-dessus de 0,5, et la liaison Entrée annulait
  l'activation clavier de tous les boutons du chrome. Les deux ont été
  reproduites, corrigées et re-vérifiées.

Deux points restent à la main de l'humain, décrits en fin de journal : la
vérification visuelle du suivi de densité (⌘+/⌘−, impossible à piloter en
headless — Chromium met à jour `.matches` sans émettre `change` sous émulation)
et quatre imprécisions de commentaire parquées.

Les chemins `.superpowers/sdd/…` cités plus bas désignent un espace de travail
temporaire, supprimé depuis : l'historique git est désormais la référence.

## Rulings

Ruling 1 (T13) — The plan's zoom-floor test targets a helper that does not exist. Correction: use the file's real `mountCamera()` (camera.test.ts:105) and extend it in place to (a) add `getBoundingClientRect: () => ({ left: 0, top: 0, width: 1000, height: 800 })` to the fake canvas and (b) return `wheel: (init) => handlers.get("canvas:wheel")!({ preventDefault(){}, deltaX: 0, deltaY: 0, deltaMode: 0, ctrlKey: false, metaKey: false, clientX: 500, clientY: 400, ...init })`. Existing tests keep working — the helper only gains members. Why: the plan's assertions are right, only their driver was invented. Cost if wrong: the wheel-driven assertions need reworking into direct `zoomOutFloor()` reads; the floor itself is still proven.

Ruling 2 (T14) — `contrastRatio` moves to `packages/tokens/src/contrast.ts` and is exposed through a NEW `"./contrast"` subpath export in the package's `exports` map (and its `build` script's tsup entry list), NOT through the index. Why: the index's own doc contract says it stays pure data so the Pixi renderer pays no cost for the DOM shell's helpers — that is precisely why `css.ts` is already outside it, and ADR-0027 is the standing decision. Importers become `@defsquare/data-graph-tokens/contrast`. Cost if wrong: one extra subpath in the package manifest that nobody but the test and the playground uses.

Ruling 3 (T16) — The `SemanticNode` fixtures gain `color: "#3dbf9e"` (any theme colour; `drawSemanticLabels` does not read it, but the type requires it). Why: the interface is verified at `draw.ts:1521-1534`. Cost if wrong: none — a required field filled with a valid value.

Ruling 4 (T1) — The third e2e test's `window.__themes` lookup is dropped; it calls `setTheme({ accent: { selection: "#00ff00" } })` directly. Why: a partial override is a legitimate `ThemeOverride`, triggers the same `rebuild()`, and changes no count — which is exactly what the test asserts. `smoke.spec.ts` already proves partial overrides are accepted. Cost if wrong: none — the assertion is unchanged.

Ruling 5 (T10) — The first e2e test's weak assertion stands as written, and the plan's own note stays: the pan DECISION is proven exhaustively in `camera.test.ts` (`revealPan`, 7 cases), and driving the camera to a known transform through synthesised wheel events is brittle enough to be worse than the unit proof. The e2e test's job is to show the wiring runs without error on a real instance. Cost if wrong: a regression where `followRevealed` is wired to the wrong hook would pass e2e; the unit tests and the second e2e test (no camera theft when content is in frame) still bound it.

Ruling 6 (T8) — T8's `main.ts` edit must keep T3's `onDiagnosticsOpen` hook in the `createChrome` call. Why: the two hooks are independent and T3 lands first. Cost if wrong: the diagnostics link goes dead — caught by `diagnostics.spec.ts`, which stays in the suite.
